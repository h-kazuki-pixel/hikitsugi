# デモの場面の再現

設計書 4-1 の場面を、デモ用ワークスペース「サンプル自習室」と demo 環境(https://hikitsugi-demo.h-kazuki.workers.dev)で再現する。登場するのはすべて架空のデータ(seed/demo.mjs)。

## 前提

- demo 環境に最新の main がデプロイされている(GitHub Actions deploy-demo)
- Slack: #天神店 にボット hikitsugi-demo が入っている。あおい(スマホ)・はると・みお・そうたが招待済み
- Secret `DEMO_SLACK_IDS` で実際の Slack ID と seed が結びついている(deploy-demo のログに「6 件の結びつけ」)
- 撮影はオーナー(橋本)のアカウントと、あおいのスマホの2画面

## 状態を戻す

seed は `INSERT OR IGNORE` なので、報告・検出・下書きは残る。やり直すときは demo の D1 を作り直す:
1. Cloudflare ダッシュボード → D1 → hikitsugi-demo → 全テーブルを削除(または DB を作り直して database_id を wrangler.toml に書く)
2. Actions → deploy-demo → Run workflow(マイグレーションと seed が当たる)
3. 11/3 以降は祝日・土曜(休業日)に注意: 店舗ページに「休業日」が出る。休業日の場面はこれを使う

## 場面1: 受付と聞き返し(0:40〜)

1. あおいのスマホで #天神店 にゴミ置き場の写真を送る(本文なしでよい)
2. スレッドに受付が返る: ねぎらい + 受け付けた箇所 + (確信が低ければ)問い1つ
3. 問いが来たら、あおいがスレッドで答える → お礼が返り、店舗ページのボードが変わる(版2)
4. 店舗ページ /stores/tenjin を映す: ゴミ置き場が「完了」

## 場面2: 引き継ぎ帳と休業日(1:25〜)

休業日(土曜・祝日)に撮る。平日なら seed の休業日(11/23)に合わせるか、「休業日なので遅れるかも」の一文がない形で撮る。
1. あおいがボット hikitsugi-demo に DM「寒いけど暖房上げていい?」→ 「25度までは自由に上げていい。それ以上にしたいときは一声かけて。(9/14 デモオーナーの回答)」
2. 続けて DM「加湿器って置いていい?」→ 「オーナーに確認します。答えが来たら、このスレッドに返します。今日は休業日なので、返事が遅れるかもしれません。」
3. オーナーの Slack にボットから DM「【引き継ぎ帳】…」が届く
4. (翌日の体で)オーナーがその DM のスレッドで「加湿器は置いていい。ただし床置きはだめ。」と答える
5. あおいのスレッドに答えが返り、オーナーには「ルール候補にしました: ルール6「加湿器は机上のみ可」」
6. 店舗ページ → ルール候補「この答えをルールにしますか」→ 承認してルールにする → ルール一覧に「由来: 引き継ぎ帳(…の質問、…の回答)」

## 場面3: 山場(2:00〜)

1. (翌週の体で)はるとが #天神店 に、床に置いた加湿器が写った清掃後の写真を送る(実物の小さな加湿器か、それらしい物を床に置いて撮る)
2. スレッドには受付だけが返る(ルールの話はしない)
3. オーナーの DM に「ルール6「加湿器は机上のみ可」に当たりそうな様子がありました(11/x のスタッフの質問から生まれたルール)」
4. 店舗ページ → 検出事項「ルールに該当」→ 判断経路を開いた状態で映す: 投稿を受け取る → 写真と本文を読む → ルール6に該当 → ルールの由来 → 見えたこと → 対応

## 場面4: 夜の突き合わせと承認(前振り、0:55〜)

1. 店舗ページ「デモの操作」→ あおい / 2時間半前 → 入室を記録する
2. 「夜の突き合わせ」→ いま動かす(キューで数十秒)
3. ページを再読み込み: 「承認待ちの下書き」にあおいへの声かけ文、「検出事項」に判断経路(入室記録を読む → 報告を読む → 名簿を見る → ルール一覧を参照 → 報告なし → ルール2に該当 → 声かけ文を下書き)
4. 承認して送る → あおいのスマホに DM が届く
5. 取り下げを見せるなら: 承認する前にあおいが報告を送る → 検出が「取り下げ」になり下書きが消える

## 撮影のコツ

- 画面は写真ではなく判断経路に寄せる(禁止例「画像解析ツール」との距離)
- 用語を使わない: 「自動応答」「チャットボット」「FAQ」「RAG」は言わない
- Worker のログ(Cloudflare → Observability)で `outcome` 行を見れば、各場面が通ったか確かめられる
