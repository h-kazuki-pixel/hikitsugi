# デモの場面の再現

台本(設計書 4-1)の場面を、デモ用ワークスペース「サンプル自習室」と demo 環境(https://hikitsugi-demo.h-kazuki.workers.dev)で再現する。登場するのはすべて架空のデータ(seed/demo.mjs)。
**撮る順は台本の順(場面1 → 2 → 3)。** 場面2で承認したルール6を、場面3で使う。

## 前提

- demo 環境に最新の main がデプロイされている(GitHub Actions deploy-demo)
- Slack: #天神店 にボット hikitsugi-demo が入っている。あおい(スマホ)・はると・みお・そうたが招待済み
- Secret `DEMO_SLACK_IDS` で実際の Slack ID と seed が結びついている(deploy-demo のログに「6 件の結びつけ」)
- 撮影はオーナー(橋本)のアカウントと、あおいのスマホの2画面
- 役の割り当て: あおい = 要確認と休業日の質問 / みお = 夜の突き合わせ / はると = 山場の写真
  (夜の突き合わせは、入室のあとに同じ人が報告を送ると検出が取り下がる。あおいは場面1で報告を送るので、夜の場面はみおで撮る)

## 撮影の注意

- **reset-demo のあとに通した検出だけが新しい文言になる。** それより前に積まれた検出事項・判断経路は古い書き方のまま残るので、撮る前に必ず状態を戻す
- **休業日の場面は土曜に撮る。** 「(土・休業日)」の表示も、「今日は休業日なので、返事が遅れるかもしれません。」の一文も、休業日に送った質問にだけ付く。山場は前半も後半も同じ土曜に続けて撮るので、判断経路とルール一覧の日付は全部その土曜になる(日付は実際に送った日から作られる。「翌日」「翌週」の日付にはならない)
- **冒頭(0:00〜0:25)と締めはデモ環境を使わない。** このスキルが扱うのは場面1〜3だけ
- **場面のあいだは5分あける。** 同じ人の続けての投稿は1件の報告に畳み込まれる(二重送信の扱い)。別の報告として見せたいときは間をあける
- **画面収録は 1280×720、明るい表示。** 判断経路の表(山場の6行・夜の7行)が2ペインのままスクロールなしに収まる大きさで確かめてある
- **画面は区画ごと(`?view=`)。** 1画面に見どころを1つ: 今日のボード(board)/ 承認待ち(approvals)/ 検出事項(findings)/ ルール(rules)/ 備品切れ(supplies)/ デモの操作(demo)。左のナビで移る
- 用語を使わない: 「自動応答」「チャットボット」「FAQ」「RAG」は言わない

## 状態を戻す

GitHub → Actions → **reset-demo** → Run workflow。確認の欄に「demo」と入れて実行する(2〜3分)。
demo の D1 の全テーブルを消し、マイグレーション → 架空の seed → Slack ID の結びつけ → デプロイをやり直す。
seed の店・人・ルール1〜5・知識10件に戻り、報告・検出・ルール候補・消費の記録は消える。production には流れない。

### Slack の DM を片づける(任意)

reset-demo が戻すのは D1 だけで、Slack のメッセージは残る。引き継ぎ帳の DM(場面2)を撮り直すとき、前のやりとりを画面に残したくなければ:

1. Slack アプリで、あおいがボットに送った質問(スレッドの親)を長押し → 削除する。返信のあるスレッドの親は「このメッセージは削除されました」として残る
2. 手元の端末で `scripts/demo/clean-dm-threads.py` を動かし、その下に残ったボットの返信を消す。トークンは Slack のアプリ設定(hikitsugi-demo → OAuth & Permissions)の Bot User OAuth Token を、その場で環境変数に入れる(ファイルにもセッションにも置かない)。どの DM かは、相手(あおい)のメンバーID(プロフィール → ︙ → メンバーIDをコピー)を `SLACK_USER` に入れて指定する(DM の ID が分かっていれば `SLACK_CHANNEL` でもよい)
   ```bash
   python3 scripts/demo/clean-dm-threads.py            # 確認のみ(消す対象を一覧する)
   python3 scripts/demo/clean-dm-threads.py --delete   # 実際に消す
   ```
   `--all` を付けると、親が残っているスレッドのボットの返信も対象になる。ボット以外(あおい・オーナー)の返信はボットのトークンでは消せないので、件数が出たら Slack アプリで消す
   使うスコープは im:history・im:write・chat:write(demo のマニフェストにある)。im:read はないので、`SLACK_USER` も `SLACK_CHANNEL` も入れずに動かすと conversations.list が missing_scope で止まる
3. オーナー側の DM(「【引き継ぎ帳】…」「ルール候補にしました」、場面3の「【サンプル自習室 天神店】ルール6…」)は、親がボットの投稿なので `--parents` を付けて消す。`SLACK_USER` にはオーナーのメンバーIDを入れる
   ```bash
   python3 scripts/demo/clean-dm-threads.py --parents            # 確認のみ([親] の行がボットの親メッセージ)
   python3 scripts/demo/clean-dm-threads.py --parents --delete   # スレッド内のボット返信 → 親の順に消す
   ```
   消すのはボット自身の投稿だけで、オーナーの投稿・返信には触れない。オーナーが引き継ぎ帳のスレッドに書いた答えは残り、親は「このメッセージは削除されました」として残るので、案内が出たら Slack アプリでその返信を消す

## 場面1: 前振り(0:25〜1:15)

### 1-a 受付と要確認

1. あおいのスマホで #天神店 に、紙くずが残ったトイレの床の写真を送る(本文なしでよい)
2. スレッドに受付が返る: ねぎらい + 受け付けた箇所 + 「写真で見えたもの: …。片づけてもらえますか? 終わったらこのスレッドに一言ください。」
3. 店舗ページ `/stores/tenjin?view=board`(今日のボード)を映す: トイレが「要確認」、その下に「写真で見えたもの: …」
4. あおいが同じスレッドに、きれいになった床の写真を「片づけました」と返す
5. スレッドにお礼が返る(例「ありがとう!完了で記録しました。」。文面は Claude が書くので多少変わる)
6. 店舗ページを再読み込み: トイレが「完了(写真で確認)」

写真にまだ紙くずが見えると「ありがとう。写真ではまだ見えるので(…)、要確認のまま残しておきます。」が返り、要確認のまま残る。撮り直すなら写真を替えて同じスレッドに送る。

### 1-b 夜の突き合わせと承認

(1-a から5分あける)
1. `/stores/tenjin?view=demo`(デモの操作)→ みお / 2時間半前 → 入室を記録する
2. 同じ画面の「夜の突き合わせ(ふだんは 21:30 に自動で動く)」→ いま動かす(キューで数十秒。承認待ちに移る)
3. `/stores/tenjin?view=approvals`(承認待ち)に戻る: みおへの声かけ文がキューに出る(承認待ちがあるときは `/stores/tenjin` を開いてもここが開く)
4. 「検出事項と判断経路を見る →」を押す → `?view=findings&id=…`(検出事項)で「みおさんの報告が届いていない(◯:◯ に入室)」が選ばれ、右に判断経路の表7行(入室記録を読む → 報告を読む → 名簿を見る → ルール一覧を参照 → 報告なし → ルール2に該当 → 声かけ文を下書き)が1画面に収まる。担い手の欄が Claude(ツール)→ Claude と並ぶところを映す
5. 承認待ちに戻って「承認して送る」→ 「送信済み」の行とトースト「みおさんに送りました」→ みおの Slack に DM が届く

取り下げを見せるなら: 承認する前にみおが #天神店 に報告を送る → 承認待ちから下書きが消える(取り下げた検出は店舗ページの検出事項からも消える。見せられるのは「下書きが消える」まで)。

## 場面2: 山場の前半(1:15〜) 引き継ぎ帳と休業日 → ルール6の承認

**土曜に撮る**(撮影の注意を参照)。
1. あおいがボット hikitsugi-demo に DM「寒いけど暖房上げていい?」→ 「25度までは自由に上げていい。それ以上にしたいときは一声かけて。(9/14 デモオーナーの回答)」
2. 続けて DM「席に財布が置きっぱなしだけど、どうすればいい?」→ 「オーナーに確認します。答えが来たら、このスレッドに返します。今日は休業日なので、返事が遅れるかもしれません。」
3. オーナーの Slack にボットから DM「【引き継ぎ帳】…」が届く
4. オーナーがその DM のスレッドで「財布や携帯などの貴重品は、スタッフだけが開けられる7番のロッカーに保管して。そのほかの忘れ物は、用具棚の忘れ物BOXへ。どちらも、見つけた場所と時間を書いて、忘れ物の写真もつけて報告して。」と答える
5. あおいのスレッドに答えが原文のまま返り、オーナーには「ルール候補にしました: ルール6「…」」(ルールの文面は Claude の下書き)
6. `/stores/tenjin?view=approvals`(承認待ち)→ ルール候補「この答えをルールにしますか」を映す → 承認してルールにする(ルール一覧 `?view=rules` に移る)
7. ルール一覧のルール6に「スタッフの質問から: ◯/◯(土・休業日) あおいさんの質問 → ◯/◯(土・休業日) デモオーナーの答え」の帯が出る

## 場面3: 山場の後半(〜2:30) 別のスタッフの写真 → ルール6に該当

(場面2から5分以上あけて、同じ土曜に続けて撮る)
1. はるとが #天神店 に「床やりました」と、デスクの上にスマートフォン(撮影用の私物でよい。画面は伏せる)が写った清掃後の写真を送る
   - **床やデスクに紙くずなどが写らないようにする。** 汚れが見えると要確認の依頼が先に立ち、ルール6の答えはスレッドに返らない
2. スレッドに受付と「デスクの上にスマートフォンが残っているようです。前にオーナーが答えたやり方です:「…7番のロッカー…」(◯/◯ デモオーナーの回答)」が返る
3. オーナーの DM に「【サンプル自習室 天神店】ルール6「…」に当たりそうな様子がありました(◯/◯ のスタッフの質問から生まれたルール)」
4. `/stores/tenjin?view=findings`(検出事項)→ 一覧の先頭「ルール6に該当 — はるとさんの報告」が選ばれ、右に判断経路の表6行が出る。映すのはこの6行:
   投稿を受け取る(承認済みのルールと照らし合わせた)→ 見えたこと → **ルール6に該当** → **元になった質問** → オーナーの答え → 対応
   (太字の2行が目立つ。担い手は 仕組み → Claude → Claude → 人の言葉 → 人の言葉 → 仕組み。元になった質問とオーナーの答えには、どちらも撮影した土曜の日付と「(土・休業日)」が付く)

## 予備: ゴミ置き場の受付と聞き返し

台本から外した場面。尺が余ったとき、または聞き返しを見せたいときに撮る(場面1〜3のあとに、5分あけて)。
1. あおいのスマホで #天神店 にゴミ置き場の写真を送る(本文なしでよい)
2. スレッドに受付が返る: ねぎらい + 受け付けた箇所 + (確信が低ければ)問い1つ
3. 問いが来たら、あおいがスレッドで答える → お礼が返り、店舗ページのボードが変わる(版2)
4. 店舗ページを映す: ゴミ置き場が「完了」

## 撮影のコツ

- 画面は写真ではなく判断経路に寄せる(禁止例「画像解析ツール」との距離)
- Worker のログ(Cloudflare → Observability)で `outcome` 行を見れば、各場面が通ったか確かめられる
